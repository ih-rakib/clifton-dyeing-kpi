## What this is

A static dashboard (HTML + CSS + vanilla JS + Apache ECharts) fed by a small Python
ETL pipeline (`openpyxl`) that reads two Excel workbooks:

| Workbook | Sheets used |
|---|---|
| `DYEING PERFORMANCE OVERVIEW.xlsx` | `Production Report`, `RFT Report` |
| `FINISHING PERFORMANCE OVERVIEW.xlsx` | `Database`, `Summary` |

The pipeline writes a single data bundle:

```
dashboard/data/data.js     # window.DASHBOARD_DATA = {...}   (loaded by the page)
dashboard/data/data.json   # same payload, for tooling / APIs
```

---

## Run it locally

```bash
pip install -r requirements.txt
python scripts/build.py         # rebuild data.js from the workbooks
```

Then open `dashboard/index.html` in a browser. It works straight from `file://`.

**Windows one-click:** double-click `start_dashboard.bat` — it installs dependencies
if needed, builds the data, opens the dashboard and then watches the workbooks,
rebuilding automatically every time you save an Excel file.

## Deploying (GitHub Pages)

The site is published automatically by the workflow in
[`.github/workflows/deploy.yml`](.github/workflows/deploy.yml).

It runs **only when you push to `main`** (or when you click **Run workflow** in the
Actions tab). It does **not** run on a schedule and does **not** create GitHub
Releases — it simply rebuilds `data.js` from the committed workbooks and redeploys
the site.

### One-time setup

1. Create an empty repository on GitHub (e.g. `dyeing-kpi`).
2. Push this project to it:

   ```bash
   git remote add origin https://github.com/<your-user>/<repo>.git
   git push -u origin main
   ```

3. In the repository: **Settings → Pages → Build and deployment → Source =
   "GitHub Actions"**.
4. Wait for the first workflow run to finish. Your site will be live at:

   ```
   https://<your-user>.github.io/<repo>/
   ```

### Everyday update loop

1. Add the new dates/rows to the Excel workbook(s).
2. Commit and push:

   ```bash
   git add "*.xlsx"
   git commit -m "data: add <date> production data"
   git push
   ```

3. GitHub Actions rebuilds `data.js` from the workbooks and redeploys. Refresh the
   site in ~1 minute.

> `dashboard/data/data.js` is regenerated by the workflow on every deploy, so you do
> **not** have to run `python scripts/build.py` before pushing.

## Notes

- **Data is committed to the repository.** Because the site is public, everything in
  the workbooks (buyer names, volumes, machine performance) is publicly visible on
  the live URL. Keep this in mind before adding sensitive rows.
- The `data.js` payload is compacted JSON; `data.json` is the human-readable copy.
- Ramifications of the 6 MB workbook: each revision is stored in git history. If the
  repository grows too large, consider Git LFS or the "commit only generated
  `data.js`" workflow.
